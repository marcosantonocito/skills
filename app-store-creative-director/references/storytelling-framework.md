# Screenshot storyboarding

Offer **5–8** frames by default, shorter if fewer credible use cases. Never inflate the count just to fill slots. For Google Play, also respect the limit of 8 per device type, and consider 4 phone screenshots for promotional eligibility. For Apple, respect 10 per device size.

| Position | Narrative job | What must be visible |
|---|---|---|
| 01 | Immediate outcome: reason to care | Most representative/highest-value real screen |
| 02 | Core action: what users do | Main workflow capture |
| 03 | Differentiator: why this app | Authentic feature with a specific benefit |
| 04 | Confidence and fluency | Workflow state users can genuinely reach |
| 05 | Secondary value | Real add-on experience |
| 06–08 | Optional deeper feature or benefit | Only if persuasive and nonrepetitive |

For each proposed shot prepare: `id`, `source_capture`, `benefit`, `headline`, `subheadline_optional`, `visual_treatment`, `claim_verification`, `locale`, `target_platforms`, and `approval_status`.

Headlines should communicate a user outcome, not generic feature labels. Avoid unverified superlatives and copy that Google discourages. Have users approve wording and verify each screenshot proves it.
